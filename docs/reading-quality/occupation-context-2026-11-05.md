# 직업 정보 과잉 대입 조정

## 원인과 조정

공통 집필 지시가 직업 정보를 생활 장면에 적극 반영하도록 하고 거래처·고객·납기 사례까지 제공했다. 인생총운에서 직업이 모든 성향을 설명하는 근거로 확대될 위험이 있었다.

- 공통 유료 웹·PDF 프롬프트: 원국과 운에서 결론을 도출하고 사용자 직업에서 성격·재정 상태를 역추론하지 않는다. 정재=고객 계약, 편재=거래처 등의 고정 치환과 영업직=성과급·매출·미수금이라는 가정을 막는 지시를 추가한다.
- 총운 계열(life/newyear/ziwei): 서버에서 설계 단계의 사용자 진술 중 occupation 답변을 분리한다. 본문 단계에서는 직업·사업·진로 장에만 chapterContexts로 직업을 배정한다. 여러 장을 한 요청으로 생성할 때도 적용 가능한 장 ID가 명시된다.
- 나머지 실제 고민과 상황은 유지한다. 직업 전문 상담은 직업 정보가 본질적이므로 보존한다. 사용자 자유 질문에 직접 적힌 직업·재정 고민은 삭제하지 않는다.
- 재물 장은 실제 재성 구조와 운, 수입·소비·저축의 판단 기준을 먼저 다룬다. 확인하지 않은 소득 구조를 생성하지 않는다.
- 기본 거래처 예시와 신년 직업 장의 영업직 예시를 삭제한다. 직업 장에서도 적용 사례는 한 문단으로 제한한다.
- report의 contextPolicy가 지문에 포함되어 구형 집필 정책의 캐시와 일치하지 않는다. 기존 주문의 접근 기간·소유권·결제·계산 엔진은 바꾸지 않는다.

## 검증

occupation-context-regression: 총운 3종 × 직업 3개, 직업 없는 설계 입력, 혼합 요청에서 직업 장에만 문맥 배정, 재물 단독·PDF 직업 제외, 실제 고민 보존, 직업 전문 상품 개인화 유지 확인.
life-opening-balance-regression: 이전 도입부 개선과의 호환 확인.
