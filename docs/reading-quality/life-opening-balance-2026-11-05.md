# 인생총운 도입부 생활 균형 조정

## 원인

기존 본성 첫 장은 입력 직업의 장면을 우선하도록 요청했고, 둘째는 책임·평가·압박과 사회생활을 고정 주제로 삼았다. 공통 서버 프롬프트도 거래처·납기·책상·고객 예시를 제시했다. 이 조합이 서로 다른 원국 근거를 업무 사례로 반복 번역하게 유도했다.

## 변경

- 프롤로그의 세 특징을 성격·감정, 친밀한 관계, 즐거움·생활에서 실제 근거에 맞게 선정하도록 요청한다.
- 본성 세 장의 계산 근거 분담은 일간·계절 / 실제 십성 관계 / 실제 합충·상반 신호로 유지한다. 독자가 읽는 질문은 본성·감정 반응 / 마음이 편해지는 조건 / 가까운 사람과의 거리 조절로 나눈다.
- 직업 정보는 그대로 보존하고 직업·재물 등 관련 장에서 활용한다. 업무 압박을 관계·취미 장에 자동 대입하지 않는다.
- 긍정적 경험이나 특정 갈등을 지어내지 않는다. 해당 관계 신호가 없으면 실제 자료에 맞는 주제를 택한다.
- 서버의 life 전용 정책은 웹·PDF, 설계·본문 단계에서 함께 적용한다. 구형 클라이언트의 직업 사례 지시보다 생활 균형 정책을 우선한다.
- PDF는 같은 원고 설계와 질문을 사용한다. 새 질문이 reportFingerprint에 들어가므로 구형 설계의 원고와 캐시가 일치하지 않는다. 기존 주문 접근·보존 정책은 변경하지 않는다.

## 검증 범위

`tools/life-opening-balance-regression.js`: 영업직·사무직·학생 입력별 동일 계산 원본 유지, 본성 세 장 분담, 직업 장 개인화 유지, PDF 지시 유지, 구형 설계와 캐시 지문 차이, life 전용 서버 정책 범위 확인. 실제 모델의 완성 원고 평가를 대신하는 테스트는 아니다.

운영 배포 및 실제 생성 원고의 서술 품질 평가는 별도이며, 이 문서 작성 시점에는 수행하지 않았다.
