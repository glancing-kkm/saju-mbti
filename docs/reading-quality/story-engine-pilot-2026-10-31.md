# 통합 해석·스토리텔링 엔진 — 1차 로컬 검토

## 현재 상태

사용자가 승인한 대표 상품에 공통 모듈을 연결했다. 운영 배포와 기본 모드 전환은 하지 않았다. `window.FortuneStoryConfig={enabled:true}`로 시범 모드를 켜며, 설정이 없거나 `enabled:false` 또는 `mode:'legacy'`이면 기존 경로를 사용한다. 저장된 유료 과거 리포트를 일괄 덮어쓰지 않는다.

## 네 핵심 기능이 함께 작동하는 방식

1. **PART 13 근거 추적**: 어댑터가 기존 계산값을 복사해 `source_reference`, `source_value`, 해석 방법, 기간, 한계를 가진 신호를 만든다. 사용자 진술은 신호와 분리한다.
2. **PART 8 자동 선택**: 상품·질문·실제 관계·계산된 기간에 따라 주 서사와 보조 서사를 고른다. 각도나 긴장 근거가 없으면 모순 발견/내면 대화 기법을 강제로 선택하지 않는다. 기간 근거가 없으면 전환점 기법을 선택하지 않는다.
3. **PART 7 기법 적용**: 선택된 기법의 전개 순서를 계산형 도입과 기존 사주 문단 순서에 사용한다. 타로는 실제 카드 조합을 전환 장에 연결한다. AI에는 같은 계획을 전달한다.
4. **PART 9 전체 연결**: 각 장에 근거와 핵심 질문을 배정하고, 실제 공유 신호가 있는 이전 장만 연결한다. 같은 문장 반복·배정되지 않은 신호·존재하지 않는 기간·구조화된 계산 주장 불일치를 검사한다.

사주·자미두수 AI 장 응답은 계획 ID, 사용한 신호 ID와 원본 계산값을 포함해야 채택한다. 기존 원본 `evidenceRefs` 검증도 함께 유지한다. 잘못되거나 불완전한 응답은 기본 계산 풀이를 보존한다. 동일 응답 묶음 및 앞서 채택한 장 사이의 문장 중복도 검사한다.

타로·점성술은 기존 Markdown API를 유지한다. 실제 카드/방향·일부 행성 별자리 주장·날짜·과장 표현·문장 중복을 검사하지만 JSON 장 응답과 동일한 수준의 구조화된 주장 증명은 하지 않는다.

## 적용 범위

- 사주 인생총운: 기존 목차를 보존하면서 서사 계획·연결·근거 보기를 연결.
- 질문형 타로: 기존 3·5·10장 배열과 카드 선택을 유지. 12개 주제의 질문형 경로에 연결.
- 점성술: 인생총운에만 연결. 다른 주제별 상품의 계산과 상품 구성을 유지.
- 자미두수: 현재 제공 중인 총운에 연결. 실제 명반의 마주 보는 지지 위치를 비교하며 이를 삼방사정 전체 분석이라고 부르지 않음.
- PDF: 기존 14개 상품 중 인생총운에만 새 계획/근거 확인을 연결. 나머지 13종은 기존 동작 유지.
- 무료: 만세력·오늘 사주에 짧은 정적 요약 연결. 무료 7종 전체의 AI 미사용은 별도 검사.

## 유지한 부분

만세력, 대운·세운·월운, 자미두수 본명반, 행성·트랜짓, 카드 선택·배열, 가격·결제·질문권·이메일 전송 코드를 새 알고리즘으로 바꾸지 않았다. 보호 대상 11개 함수의 소스가 직전 배포 커밋과 동일한지 검사했다. 비교 대상: `calcSaju`, `calcDaeun`, `yearPillar`, `monthPillar`, `buildZiweiChart`, `getSpreadPositions`, `selectDeckCard`, `seededRand`, `calculateAstrologyChart`, `calculateTransit`, `calculateTransitAspects`.

새 AI 요청을 별도로 추가하지 않는다. 기존 요청에 계획 데이터를 더하므로 유료 요청의 실제 입력 토큰량·비용은 실측해야 한다.

## 검증 결과

- 기존 12개 회귀 검사 스크립트 통과. 대표 계산·상품·결제 보호·14종 PDF의 기존 경로 유지 확인.
- 신규 시범 검사 통과: 10개 기법 라이브러리, 12개 실제 명식의 결정성/차별성, 출생시간 미상·아동 처리, 개인 사건의 계산 신호 유입 차단, 잘못된 계산값/기간/중복 거절, 정상 증거의 실제 DOM 채택, 전환 설정.
- 시범 타로 36개 조합(12주제 × 3·5·10장)의 카드 수·방향·계획·목차 확인.
- 시범 모드에서 무료 7종 + 유료 잠금 미리보기 16경로: AI/인상 이미지/번역 요청 0건. 감지 장치 양성 대조는 모의 유료 요청 2건.
- 실제 Chrome에서 4분야 × 390/1069px = 8개 배치: 가로 넘침·죽은 연결 목차 링크·페이지 스크립트 오류 0건.
- 인생총운 계산형 PDF: 실제 PDF 파일 기준 39쪽, 리포트 본문 집계 21,428자, 본문 높이 넘침 0쪽. 실제 PDF 파일을 생성하고 표지·본문·마지막 쪽을 눈으로 확인. 외부 폰트 요청을 차단한 로컬 대체 폰트 환경이며 모든 폰트/기기 조합을 보증하지 않음.
- 실제 모델·결제·이메일 호출은 하지 않았다. 브라우저 검토의 인물/질문은 명시적으로 가상 입력이며 운영 결과와 섞지 않았다.

시범 PDF의 표지·요약 필드는 구조화된 출처 증명이 없는 AI 필드를 채택하지 않고 계산형 기본값으로 채운다. 이 필드만 필요한 AI 요청은 생략하며, 본문 요청에는 같은 계획과 결말 연결 기준을 전달한다.

## 한계와 후속 확인

- 이 결과는 **1차 구현과 로컬 검증**이다. 실제 유료 AI 문장의 자연스러움·근거 충실성·비용·응답시간은 아직 실측하지 않았다.
- 계산값 복사와 ID 일치는 의미 전체의 논리적 타당성을 증명하지 않는다. 문장 규칙 검사는 모든 잘못된 해석·우회 표현을 잡아내는 장치가 아니다.
- 점성술 솔라 리턴·하우스 지배성, 자미두수 유년·유월·삼방사정·보조성/살성 전체, 사주 격국/조후/용신의 새 학파 판정은 구현하지 않았다. 원래 없던 결과를 서사로 만들지 않는다.
- 자미두수는 현재 코드가 제공하는 내장 간이 명반 규칙으로 표시한다. 특정 전통 학파의 완전한 구현임을 주장하지 않는다.
- 기존 도입 사건 카드·점수표·모든 일반 문장을 새 신호 모델로 완전히 이관하지 않았다. 기존 계산형 본문을 재사용하는 부분이 있으며, 전체 카테고리/PDF의 전면 개편은 2차 범위다.
- 도입과 결말의 의미적 회수는 AI에 설계로 전달하며, 실제 문학적 완성도는 샘플을 읽는 검토가 필요하다. 현재 사용자용 제목·가격·상품을 임의로 삭제하지 않았다.

검토 샘플과 브라우저 측정 결과는 `/tmp/fortune-story-review/`에 있다. 운영에 적용하기 전 사용자 샘플 확인 → 실제 유료 AI 출력 검증 → 필요한 문장/검증 보완 → 배포 확인 순서로 진행한다.

## 운영 전환 순서

Worker의 새 응답 규칙을 먼저 배포하고, 웹은 시범 전환을 끈 상태로 올린다. 실제 유료 AI 결과·비용·응답시간을 확인한 뒤 중앙 `FortuneStoryConfig.enabled`를 켠다. 문제가 있으면 `enabled:false`로 기존 경로를 복구한다. 기존 계산/결제 및 과거 유료 기록은 그대로 유지한다. 이번 작업에서는 위 배포 단계를 실행하지 않았다.

로컬 검토 모음: `http://127.0.0.1:8779/` (프로젝트 정적 자산 서버 8778과 함께 로컬에서만 실행). 검토 자료는 `/tmp`에 있으며 Git/운영 배포에 포함하지 않는다.
