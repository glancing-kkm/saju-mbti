## 발견한 문제와 수정

1. **정상 문장을 근거 오류로 오인해 재작성하던 문제**: 계산된 연도나 배정된 월을 실제로 설명했지만 근거 ID가 빠진 경우, 해당 계산 원본과 장의 배정 범위 안에서 메타데이터만 복구한다. 없는 연도나 누락된 월 설명은 여전히 거절한다. ‘일간에 갑목의 생조가 더해진다’를 ‘일간이 갑목이다’로 오인하던 검사도 구분했다.
2. **한국어 본문의 외국어 혼입**: 실제 응답에 섞인 `अस्पष्ट`는 뜻을 바꾸지 않고 ‘불분명’으로 교열한다. 그 밖의 해당 외국 문자 혼입은 검증에서 잡는다. 한국어와 숫자를 잘못 거절하지 않는 회귀 검사도 추가했다.
3. **반복 설명**: 병렬 집필에 십성 용어의 최초 설명 담당 장을 전달하고, 총론과 개별 장의 역할이 충돌하던 집필 지시를 정리했다. 계산형 원고의 ‘성격이 두 배’와 점수만으로 성과를 약속하는 문장은 제거했다. 타로 계산형 원고는 카드 뜻을 여러 장에서 그대로 반복하지 않고 카드별 상세 장에 모았다.
4. **이름의 미확인 한자**: 확인 상태가 비어 있는 자동 후보도 기본적으로 미확인으로 취급한다. 이 경우 한자 뜻·획수·수리 자료를 집필에 전달하지 않으며, 한자·획수 전용 두 장을 제외한다. 실제 사용 한자 또는 검토 후보를 명시하면 해당 자료·장을 유지한다. 계산식 자체는 변경하지 않았다. 발음오행의 분류를 실제 발음의 편리함에 대한 인과 근거로 사용하지 않도록 지시했다.
5. **PDF 심화와 출력**: 웹의 이야기·결론을 유지하면서 월·연도별 이유와 조건을 더 설명하도록 PDF 지시를 분리했다. 글자 수 목표는 참고 기준이며 분량만으로 품질을 통과시키지 않는다. PDF 집필은 기존 두 묶음에서 최대 세 묶음 동시 처리로 바꿨다. 계획을 다시 생성하거나 전체 요청 수를 늘리는 방식은 아니다.
6. **실제 PDF의 글자 누락·쪽 나눔**: HTML 화면에는 글자가 있지만 인쇄 PDF에는 빠지는 사례를 재현했다. 독립 인쇄 문서의 글꼴을 `display=swap`으로 바꾸고, 서버는 글꼴 스타일시트가 포함된 문서의 `load` 이후 `document.fonts.ready`를 기다린다. 마지막 근거·조언 상자는 직전 본문과 묶어 홀로 다음 쪽에 남지 않게 했다. API 동작은 [Puppeteer setContent](https://pptr.dev/api/puppeteer.page.setcontent), [PDFOptions](https://pptr.dev/api/puppeteer.pdfoptions) 공식 문서도 참고했다. 글꼴 누락의 원인과 수정 효과는 이번 로컬 재현·파일 검사 결과다.

## 실제 검증 범위

- 사주 계열 **14개 상품의 웹과 PDF**: 인생총운, 신년운세, 궁합, 이름, 자미두수, 주제별 9종. 실제 모델 응답을 현재 근거·기간·본문 검증기에 대조했다.
- **타로 12주제·점성술 12주제**: 실제 카드·차트와 운영의 스토리 계획/프롬프트 빌더를 사용했다. 각 응답이 해당 검사에 최종 통과했다. 첫 응답 성공률이나 전체 운영 성공률을 뜻하지 않는다.
- **웹 본문 38종 × 390px/1069px**: 현재 본문 렌더러로 그려 가로 넘침과 장 누락을 확인했다. 사주 원국·인물 이미지·결제 화면 전체를 이 검사에서 재현한 것은 아니다.
- **실제 PDF 14개, 총 253쪽**: Chromium 인쇄 후 macOS PDFKit으로 파일을 다시 열었다. 모든 쪽에 추출 가능한 텍스트가 있으며, HTML 레이아웃의 본문 넘침과 근거/조언 상자 단독 쪽은 0건이었다. 대표 PDF 페이지 이미지도 확인했다. HTML 스크린샷만 검사하지 않았다.
- 완성 웹/PDF 저장본을 같은 입력으로 다시 호출한 28개 경우 모두 **추가 API 요청 0회**였다. 입력·자료가 달라진 경우까지 무료 재사용을 보장하는 결과는 아니다.
- 최종 수정본에서 `npm test` 35개 명령이 모두 종료 코드 0으로 통과했다. 이름의 미확인 기본 처리·조건부 목차, PDF 동시 처리·페이지/글꼴 변경도 관련 회귀와 실제 브라우저/PDF 검사로 확인했다. [최종 회귀 로그](live-regression-2026-11-10.log)를 함께 보관했다. 결제와 메일은 모의 검사이며 실제 고객 거래·메일 전송은 하지 않았다.

PDF의 로컬 페이지 구성·Chromium 인쇄는 대체로 약 1~2초가 추가됐다. **Cloudflare 운영 브라우저의 실제 출력 시간, 결제/네트워크를 합친 고객 체감 시간을 측정한 수치는 아니다.**

PDF 두 묶음의 별도 인생총운 표본은 93.2초였지만, 세 묶음 표본과 글자 수·재작성 횟수가 달랐다. 따라서 특정 비율만큼 빨라졌다는 결론을 내리지 않는다. 다른 PDF 중에는 기존에 성공한 장을 재사용한 결과도 있어 JSON의 `ms`를 모두 최초 전체 생성 시간으로 읽으면 안 된다. `resumed` 값이 포괄적으로 기록된 초기 검증 파일도 있으므로 시간 비교는 위에 조건을 명시한 새 생성 표본만 사용한다.

웹은 계획 작성과 긴 출력 자체가 병목이다. 모델과 본문 분량을 유지한 현재 조건에서 **10초 완성은 검증하지 못했다**. 비용과 시간을 줄인다고 근거 검증을 끄거나 미완성 본문을 먼저 표시하지 않았다.

## 반복·상품 차이 검토

계산형·레거시 감사의 검토 항목은 **114 → 72건**, 실행 오류는 0건이다. 이 감사는 현재 결제 후 AI 집필 원고의 품질 점수가 아니다. 남은 항목에는 같은 연도·월의 근거를 여러 표에서 보여 주는 경우, 같은 조건에 같은 행동 조언이 나오는 경우가 섞여 있다. 문장만 다른 말로 바꾸거나 날짜를 붙여 수치를 낮추지는 않았다. **모든 반복감이 없어졌다고 판정하지 않는다.**

실제 유료 표본은 장마다 `newContribution`과 원고를 나란히 검토할 수 있도록 비교 페이지에 남겼다. 재물 상품은 수입원·변동성·순이익·공동 부담·회수 조건, 연애는 표현·신뢰·갈등·상호성, 직업은 업무·협업·권한·보상·경력 선택을 나누는 방식이다. 총운의 해당 영역을 늘려 복사하는 지시는 사용하지 않는다. 자동 문장 중복 검사는 의미가 비슷한 설명까지 모두 찾아내는 전문가 심사를 대신하지 못한다.

일부 상품은 PDF와 웹의 총 글자 수 차이가 작다. 분량이 늘었다는 이유만으로 깊이가 충분하다고 평가하지 않으며, 비교 표본의 실제 이유·조건 설명을 기준으로 판단해야 한다. 향후 고객 평가 없이 모든 상품의 유료 만족도가 검증됐다고 주장할 수 없다.

## 유지한 부분과 한계

- 만세력·대운·세운·월운, 카드 선택, 행성 위치·하우스·각도 계산, 자미두수 별 배치, 이름 획수 계산은 수정하지 않았다.
- 운영 GPT/Claude 모델은 변경하지 않았다. 이번 실호출 검증은 기본 GPT 경로이며, Claude 장애 대체 경로는 실제 제공자 호출 없이 기존 모의 회귀로 확인했다.
- 자미두수의 아직 계산하지 않는 유년·유월·완전한 삼방사정 확장은 하지 않았다. 계산 근거 없는 시기 분석을 새로 생성하지 않는다. 계산 규칙 확장은 별도 설계·검증 대상이다.
- 무료의 AI 미사용, 결제/상품, 기기와 24시간 제한은 회귀로 유지했다. 실제 결제·메일·운영 부하 시험, 사람 전문가의 전수 심사, 예측 적중률 검증은 이번 결과에 포함하지 않는다.
- 실제 모델을 호출했으므로 이번 검증에는 API 사용량이 발생했다. JSON의 사용량은 채택 표본의 기록이며, 디버깅·폐기·재개 이전 호출을 포함한 전체 청구액이 아니다.

## 변경 파일과 재현

서비스: `assets/ai-report.js`, `assets/reading-voice.js`, `assets/astrology.js`, `assets/report-pdf.js`, `index.html`, `worker/saju-chat-worker.js`. 기존 모듈을 고도화했으며 계산 엔진을 교체하지 않았다.

검증: `tools/prose-reference-regression.js`, 기존 관련 회귀, `tools/reading-live-review.js`, `tools/reading-md-live-review.js`, `tools/render-live-review.js`, `tools/inspect-review-pdfs.swift`, `tools/summarize-live-review.js`. 실호출 도구는 `--live`를 명시해야 요청한다. 개발용 임시 모델 엔드포인트는 종료했고 운영에 추가하지 않았다.

```sh
npm test
node tools/reading-depth-audit.js --out /tmp/calculated-audit.json
# 실제 모델 호출 없이 저장된 표본만 출력·검사

swift tools/inspect-review-pdfs.swift /tmp/saju-live-complete

```

브라우저 검증은 설치된 Chrome과 Playwright가 필요하다. `REVIEW_PLAYWRIGHT`로 별도 Playwright 경로를 지정할 수 있다. 실제 원고 생성의 입력은 가상 개발 표본이다. 이번 PDF 파일과 비교 원고는 고객 결과나 운영 데이터로 사용하지 않는다.

배포 시에는 새 집필 지시·글꼴 대기를 적용하는 Worker를 먼저, 변경된 자산 해시를 포함한 프런트를 다음에 배포해야 한다. 현재 기록은 배포 완료 보고가 아니다.

## 배포 전 최종 UI 확인

- 신년운세 최초 입력 기본값은 2027년이며, 이미 선택한 연도는 유지한다.
- 용어 설명 안내 박스는 모든 렌더 경로에서 제거했다. 개별 용어 설명 기능은 유지한다.

- 390px / 1069px Chrome에서 오늘의 타로 및 3·5·10장 선택 완료까지 확인했다. 첫 카드가 보이고, 선택 전후 가로·세로 스크롤 및 카드 좌표가 유지됐다. 중복 선택 차단·최종 풀이 버튼도 확인했다. 이 검사는 모델·결제를 호출하지 않았다.
