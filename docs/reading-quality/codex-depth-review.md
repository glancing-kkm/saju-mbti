# Codex 독립 검토 — 전체 풀이 심화 개편

## 맡은 범위

Claude는 운영 코드와 기존 회귀 검사를 포함한 전체 개편을 구현한다. Codex는 `tools/reading-depth-audit.js`와 `docs/reading-quality/codex-depth-*`만 작성하고, 같은 운영 파일을 동시에 편집하지 않는다. 초기 개편 일부가 진행된 시점의 스냅샷을 검사했으며, 최종 구현 후 같은 검사를 다시 실행해 비교한다.

## 실행한 검사

```sh
node tools/reading-depth-audit.js --out docs/reading-quality/codex-depth-baseline.json
```

- 시스템 6종: 사주, 타로, 서양 점성술, 자미두수, 베딕, 마하보테.
- 웹 생성 경로 47개: 사주/이름/월별/지정일/무료 20개, 타로 12주제, 점성술 12주제, 오늘 타로·오늘 점성술·무료 출생차트 3개.
- 281개 결과 생성: 아동·청년·성인 미혼/연애/기혼·노년·시간 미상, 타로 3/5/10장, 점성술 시간 유무 포함.
- 현재 유료 PDF 14종의 장·소제목·요청 묶음·AI 없는 대체 본문 검사.
- 가상 차트의 달 또는 각도만 바꾸는 입력 민감도 검사. 물리적으로 가능한 다른 출생차트를 만들었다는 뜻이 아니며, 해당 함수가 입력을 어떻게 소비하는지 확인하는 제한된 검사다.
- 외부 모델, 결제, 이메일 호출 없음. PDF 실제 파일/페이지 렌더링은 하지 않았고 아래 문자 수는 PDF 완성본 문자 수를 보장하지 않는다.
- 수정 파일 해시와 실행 중 변경 여부는 JSON에 기록했다. 소스가 바뀌면 최종 검사를 다시 실행해야 한다.

## 첫 검사 결과

281개 결과에서 빈 결과·미치환 값·런타임 예외는 발견되지 않았다. 그러나 생성 성공은 내용 완성도를 뜻하지 않는다. 반복 신호 155건은 교열 검토 항목이며, 모든 항목이 오류라는 뜻은 아니다. 반복 근거나 정상적인 이용 안내를 지워 수치를 인위적으로 낮추지 않는다.

### P1. PDF의 서로 다른 질문에 같은 대체 본문이 들어간다

AI 응답이 없을 때 사용하는 `rpFill → rpSourceStory` 경로에서 14개 PDF 중 13개에 정확히 같은 본문을 쓰는 서로 다른 소제목이 있었다. 아래 수치는 중복 그룹에 속한 소제목 수이며, 오류 발생 횟수나 유료 AI 응답의 중복률이 아니다.

|---|---:|---:|
| 인생총운 | 32 | 14 |
| 신년운세 | 11 | 0 |
| 궁합 | 21 | 8 |
| 이름풀이 | 21 | 19 |

실제 사례:

- 자미두수의 ‘명반을 관통하는 핵심 주제’, ‘현재 대한의 주요 주제’, ‘대상 유년의 변화’, ‘전환기에 준비할 일’이 동일한 32~41세 대한 설명을 사용했다. **대한 설명을 유년 계산 결과처럼 취급하면 안 된다.** 미구현 계산의 한계를 밝히고 질문에 맞는 범위의 해석을 써야 한다.
- 이름풀이의 ‘적용하는 성명학 체계’와 ‘본인이 중요하게 생각할 기준’이 동일한 이름 일반론을 사용했다. 후보·글자·발음·사용성의 실제 차이를 설명해야 한다.
- 직업운은 ‘일을 지속하게 하는 동기’, ‘분석과 실행의 강점’, ‘의사결정과 평가 방식’, ‘전환의 비용과 생활 기반’ 등 다른 질문에 동일한 네 문단이 반복됐다. 소제목만 바꾸거나 같은 조언을 추가해서 해결할 문제가 아니다.

요청한 수정: 장/소제목별 질문과 해당 시스템의 실제 근거를 매칭한다. 대체 본문도 소제목의 질문에 답해야 하며, 이름·궁합·자미두수를 일반 사주 성격으로 채우지 않는다. AI가 성공했을 때의 긴 설명뿐 아니라 부분 실패/재시도/대체 경로도 검증한다.

### P1. PDF 품질 판정이 길고 다른 문장이면 빈약한 설명도 받아들인다

서로 다른 두 문단에 ‘상황을 살펴보고 방향을 정리’한다는 말을 반복한 가짜 답을 넣었을 때 `rpSectionQuality`가 통과했다. 실제 모델이 이런 응답을 냈다는 뜻은 아니다. 현재 길이·문단 수·완전 동일 문단 여부만으로는 의미 있는 상세풀이를 보장하지 못한다는 검증이다.

요청한 수정: 최소 분량 외에 소제목 관련성, 장간 반복, 계산 근거 인용 범위, 사용자 진술의 출처, 미제공 연도·별/행성·사건 단정 등을 검사한다. 자동 규칙으로 모든 의미 오류를 증명할 수 있다고 주장하지 않는다.

### P1. 유료 타로·점성술의 첫 설명이 종합 해석으로 바뀌지 않는다

검사한 소스에는 미리보기 첫 섹션을 `keep=mdSections(tpl).slice(...)`로 고정한 뒤 AI 응답의 나머지만 합치는 경로가 있었다. 독자가 가장 먼저 읽는 도입이 기본 사전식 설명에 남을 수 있다.

요청한 수정: 결제 후 실제 질문과 구조화된 근거에 기반한 일관된 전체 해석이 앞부분까지 대체되게 한다. 카드/차트 사실, 미리보기 잠금, 결제 권한과 출처는 보존한다. AI 본문을 뒤에 덧붙여 웹 총량만 늘리지 않는다.

### P2. 점성술 기본 해석의 다중 근거 연결이 약하다

`astroPracticalReading`에 달 별자리만 바꾼 가상 입력을 주었을 때 12개 주제 중 아이·자녀·건강 3개만 문장이 달라졌다. 실제 각도 입력만 바꾸면 12개 모두 문장이 같았다. 이 함수 외의 무료 차트나 유료 AI가 각도를 전혀 사용하지 않는다는 뜻은 아니다. **현재 기본 해석 함수가 사실상 주제별 한 행성에 의존한다**는 한정된 결과다.

요청한 수정: 실제로 제공된 서로 다른 요구/각도/현재 트랜짓의 연결을 해당 주제의 장면·갈등·선택 기준으로 번역한다. 의미 없는 사전 문구나 행성 이름만 추가해 민감도 검사를 통과시키지 않는다. 시간 미상은 ASC/MC/하우스를 추정하지 않는다.

### P2. 무료 타로가 카드별로 달라 보이지만 생활 조언을 고정 풀에서 고른다

78개 카드 중 35개에 ‘일에서는 중간에 공유하는 게 오늘의 열쇠’라는 같은 문장이 나왔다. 29개에는 ‘돌려 말하기보다 담백하게 표현’하라는 같은 문장이 나왔다. 카드 선택 안내 78회 반복은 정상 UI이므로 교열 대상에서 제외한다.

요청한 수정: 카드의 실제 상징에서 장점과 과도한 반응의 조건, 오늘 확인할 장면을 연결한다. 카드 ID 해시로 조언만 순환하거나 문구만 바꿔 다양성 수치를 늘리지 않는다.

### P2. PDF 총량 상한과 동시 요청 수를 별도 확인한다

초기 소스는 본문이 이미 커도 `Math.max(3000,RP_MAX_CHARS-main-600)`로 부록 최소 3천 자 예산을 주었다. 이것만으로 상한을 넘었다고 단정할 수는 없지만, 상세분량 확대 시 전체 6만 자 이내라는 보장과 충돌할 수 있다.

`Promise.all(plan.groups.map(one))`도 모든 묶음을 한꺼번에 호출하므로, 상세 생성 그룹 수가 늘 때 동시성·실패 재시도·주문별 호출 한도와 함께 검토해야 한다. 실제 제공자 한도나 비용을 이번 검사에서 측정하지 않았다.

## 최종 확인에서 필요한 사항

1. 전체 47개 생성 경로와 14개 기존 PDF를 다시 검사한다. 오류 없이 생성된 것과 내용이 개선된 것을 구분한다.
2. 웹 전후 글자 수를 같은 가상 입력으로 비교한다. 본문 뒤에 설명을 일괄 추가해 개선한 것으로 판정하지 않는다.
3. AI 응답은 운영 제공자 실응답을 직접 보지 않았다면 ‘실응답 검수 완료’라고 하지 않는다. 모의 응답 채택·거절·부분 실패·개인 정보 격리 검사는 수행한다.
4. 대표 PDF는 실제 브라우저에서 생성한 페이지를 렌더링해 긴 본문·표·마지막 페이지의 잘림과 총량을 확인한다. jsdom에서 페이지 생성이 성공했다는 이유로 실제 레이아웃을 통과했다고 하지 않는다.
5. 주제별 다르게 쓰되 같은 명식의 공통 경향과 사용자 본인이 알려준 사건을 구분한다. 직업 입력이 달라져도 그것을 ‘사주로 알아맞힌 사실’로 쓰지 않는다.
6. 검사 통과 수치를 미래 예측 적중률이나 사용자 만족도 점수로 표시하지 않는다.

### P1 추가 발견. 사주 근거 검증을 자미두수의 별 배치 검증으로 오해할 수 있다

현재 자미두수 심층 AI 요청의 공통 `readingSynthesisReferences()`는 `natal.year.stem` 같은 사주 원국·세운·대운 근거만 허용한다. 자미두수의 실제 궁·주성 배치에 대응하는 구조화된 근거 ID는 없었다. 섹션의 일반 텍스트 facts에는 올바른 별이 담길 수 있지만, ID 검증을 통과했다는 사실만으로 별 배치가 맞다는 보장은 없다.

재현한 합성 오류:

- 가상 사례의 실제 명궁 주성은 **파군**이다.
- 일부러 **명궁에 자미가 있다**고 쓴 두 문단을 넣었다.
- 실제 사주 원국의 서로 다른 natal ID 두 개를 함께 주면 `readingSynthesisQuality`는 통과한다.
- 잘못된 명궁 별을 쓴 설명도 현재 `readingDeepQuality`는 통과한다.

이것은 실제 AI가 그런 오답을 냈다는 주장이 아니라, 제공된 근거 ID와 해당 시스템의 주장을 검증하는 범위가 어긋날 수 있다는 테스트다. 사용자 요청에 따라 AI 활용을 늘리기 전에 시스템별 근거를 갖추어야 한다.

요청한 수정: 자미두수는 명궁/신궁/주제 궁/대한/사화 등 실제 계산 결과를 구조화해 전달하고, 참조 가능한 ID·출력의 별/궁 배치를 해당 실제 데이터와 대조한다. 이름은 후보/한자/획수, 궁합은 두 사람과 실제 비교값, 점성술은 행성·각도, 타로는 뽑힌 카드·자리·방향이라는 각자의 근거로 검증한다. 검증할 계산이 없는 요소는 한계를 밝히고 임의로 추가하지 않는다.
